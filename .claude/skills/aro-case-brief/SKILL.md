# ARO Case Brief

ARO가 HR 스터디 모임에서 토론 자료로 쓰고 개인 학습용으로도 쌓아가는 A4 4~6쪽짜리 보고서다. 매번 낱장으로 만들어지므로 양식·톤·검증 수준이 편마다 흔들리지 않게 하는 것이 이 스킬의 목적이다.

독자는 HR 실무자·리더다. 그들이 이미 아는 이야기("AI가 일자리를 바꾼다")는 한 줄도 쓰지 않는다. 브리프의 가치는 세 가지에서 나온다: 여러 자료를 연결해 하나의 패턴을 보여주는 것, 뻔한 결론을 반박하는 상충 증거를 정면으로 다루는 것, HR이 실제로 바꿀 지표와 질문으로 끝나는 것.

## 작업 순서

### 1. 주제와 입력 정리

ARO가 주는 것은 보통 세 가지 중 하나다.
- 주제 문장이나 뉴스 요약 ("AI가 해고보다 신규채용을 먼저 바꾼다")
- 다른 AI가 만든 초안 (docx, pdf, 텍스트)
- 이전 브리프 + "이 양식으로"

아카이브 저장소 안에서 작업할 때 기초자료는 `../work/<브리프 폴더명>/`에 둔다(폴더명은 `briefs/` 아래와 동일). 없으면 만들고, 검증 결과는 그 폴더에 `verify.md`로 남긴다.

초안이 있으면 먼저 텍스트를 추출해 **주장 목록과 수치 목록**을 뽑는다. 그 수치들은 검증 대상이지 사실이 아니다. 실제로 ChatGPT 초안에서 절반 이상의 수치가 원출처에서 확인되지 않거나 방향이 반대로 인용된 사례가 있었다 (references/verification.md 참고).

### 2. 검증 조사 (가장 중요한 단계)

`references/verification.md`를 읽고 그 규칙대로 조사한다. 요점:
- 모든 수치는 발표 기관의 원문 또는 그 기관을 직접 인용한 보도에서 확인한다. 확인 안 되면 넣지 않고, 출처 섹션에 "확인 못 해 미수록"이라고 쓴다.
- 수치의 **방향**을 확인한다. 값이 맞아도 전년 대비 늘었는지 줄었는지가 초안의 논지와 반대인 경우가 있다.
- 주제와 반대되는 증거를 최소 하나 찾아 신호표와 "읽는 법"에 넣는다. 반대 증거가 없는 브리프는 미완성이다.
- 해외 대조 자료 하나를 넣을 수 있으면 넣는다. 다른 나라·다른 데이터에서 같은 결론이 나오면 "한국 특수 현상"이 아니라는 강한 근거가 된다.
- 조사 중 초안에 없던 더 강한 사실(같은 업종에서 청년은 줄고 50대는 늘었다 등)을 만나면 그것을 본문 앞쪽에 세운다. 초안은 참고일 뿐이다.

### 3. 구조 채우기

`references/structure.md`가 각 요소의 역할과 좋은 문장·나쁜 문장을 정리해 둔 문서다. 처음 쓰거나 판단이 애매하면 읽는다. 뼈대는 다음과 같다.

```
CASE BRIEF / ARO · 연월
제목(2행, 주장형) + 부제
한 줄 결론 박스
3카드 (명제 + 대조구)
왜 지금 이 문제를 봐야 하나 + 이 자료의 질문
01 신호표 (기관 / 확인된 변화 / HR이 읽어야 할 것) + 읽는 법 + HR POINT ①
02 메커니즘 (흐름 박스, 역설 표) + HR POINT ②③
03 숫자 4개 + 실무 전환 (매트릭스, 지표표) + HR POINT ④
04 HR 리더가 지금 점검할 질문 5개 + 작은 진단 5단계
FINAL INSIGHT
자료 출처 및 해석 유의사항
```

카피 원칙:
- 문장은 짧게. 주어는 HR 또는 기업이다. "청년이 힘들다"가 아니라 "기업의 내부 인재공급 구조 문제다".
- 인사이트 문장은 반드시 "그래서 HR이 무엇을 다르게 봐야 하는가"로 끝난다.
- 시나리오와 사실을 구분해 쓴다. 인과가 입증되지 않은 주장은 "입증된 사실이 아니라 HR 시나리오다"라고 문장 안에서 표시한다.
- em dash(—) 금지. 쉼표, 괄호, 콜론으로 대체. 이모지 금지. 명조(세리프) 금지, 인용구·결론 박스도 전부 산세리프.
- "혁신적", "패러다임", "함께 성장" 같은 기업 사이트 상투구 금지.

### 4. HTML 작성

`assets/template.html`을 복사해 `{{ }}` 자리를 채운다. CSS는 손대지 않는다 (ARO 브랜드 컬러와 5단계 타이포가 이미 들어 있다). 완성된 실제 예시는 `references/example-career-ladder.html`이다. 구조를 확인할 때 열어본다.

레이아웃 규칙 (템플릿 클래스로 처리됨):
- 섹션 01 제목은 `pb` 클래스로 항상 새 페이지에서 시작
- 제목과 첫 블록은 `<div class="avoid">`로 묶어 고아 제목 방지
- 표는 `thead`/`tbody` 구조 유지 (페이지 넘김 시 헤더 반복)
- 강조 열은 `hl`, 콜아웃은 `hp`(초록)와 `box`/`flowbox`(베이지) 두 종류만
- 줄바꿈은 `word-break: keep-all` + `overflow-wrap: anywhere`(템플릿에 있음). 단어 중간에서 끊지 않는다. 오른쪽 끝이 들쭉날쭉한 것은 정상이며 `normal`로 바꾸거나 `text-align: justify`를 넣지 않는다. check_brief.py가 이를 점검한다.

### 5. 렌더와 점검

```bash
python3 scripts/render_pdf.py 파일명.html            # A4 PDF 생성 (Pretendard 자동 다운로드)
python3 scripts/check_brief.py 파일명.html           # em dash·이모지·미치환 자리·필수 요소 점검
```

PDF를 페이지 이미지로 렌더해서 직접 본다. 확인할 것: 제목만 페이지 끝에 남는 고아 제목, 마지막 페이지에 출처만 홀로 남는 경우(허용되지만 앞 페이지 여백이 크면 조정), 표 헤더만 떨어진 경우. 5~6쪽이 정상 범위다.

### 6. 전달

PDF와 HTML을 함께 주고, 아카이브에 올라간 뒤에는 공개 URL을 함께 준다. 답변에는 다음을 짧게 쓴다.
- 초안 대비 **고친 것**: 틀렸거나 방향이 어긋난 수치, 확인 못 해 뺀 수치
- **새로 넣은 인사이트**: 조사 중 발견한 초안에 없던 사실
- 추측이 섞인 판단은 추측이라고 표시

### 7. 아카이브 등록

브리프는 낱장으로 끝나지 않고 아카이브에 쌓인다. 저장소와 공개 주소는 다음과 같다.

- GitHub 저장소: `aro-deeply/aro-briefs` (https://github.com/aro-deeply/aro-briefs)
- 공개 주소: https://aro-deeply.github.io/aro-briefs/
- 구조: `index.html`(목록) + `briefs/YYYY-MM-DD-slug/index.html`(웹 판) + `brief.pdf`(인쇄 판)

`references/archive.md`에 웹 판 변환 규칙, 목록 카드 양식, 로컬 저장소 경로가 있다. 등록 순서:

1. 완성 HTML을 웹 판으로 변환한다 (로컬 폰트 → CDN, 상단 nav 추가, 함께 읽기 링크). 변환 규칙은 archive.md.
2. `briefs/YYYY-MM-DD-slug/`에 `index.html`과 `brief.pdf`로 넣는다. slug는 영문 소문자와 하이픈.
3. 목록 `index.html`의 `<div id="list">` 맨 위에 카드 하나를 추가한다. CASE BRIEF 번호는 직전 편 +1, 태그는 AI 도입 / HRD / 채용 / 노동시장 / 조직설계 중에서 고른다. 새 태그가 필요하면 필터 버튼도 함께 추가한다.
4. 관련 있는 이전 편이 있으면 양쪽 출처 섹션 아래 "함께 읽기" 링크를 서로 건다.
5. Claude Code에서 작업 중이면 커밋·푸시까지 한다. 커밋 메시지는 `brief: <slug>`. 저장소가 로컬에 없으면 clone 명령을 안내하고, 웹 업로드로 진행할 경우 어느 폴더에 어떤 파일을 올리고 index.html의 어느 위치를 고쳐야 하는지 짚어준다.
6. 푸시 후 1~2분 뒤 공개 주소에서 새 카드와 본문 페이지가 열리는지 확인하고, 최종 URL을 ARO에게 준다.

## 하지 말 것

- 초안의 수치를 검증 없이 옮기는 것. 검증이 이 스킬의 절반이다.
- 반대 증거를 빼고 한 방향으로 쓰는 것. 스터디 토론이 죽는다.
- "AI가 일자리를 없앤다/없애지 않는다" 같은 총량 논쟁으로 제목을 잡는 것. 항상 HR이 통제할 수 있는 변수(채용 구조, 직무설계, 도입 방식, 지표)로 좁힌다.
- 디자인 변경. 컬러·폰트·크기를 새로 정하지 않는다. ARO 브랜드 자산은 aro-brand-style 스킬이 관리한다.
